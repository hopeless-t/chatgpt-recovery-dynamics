Core states

まず B / E / H だけ覚える

BBlocked失敗・遮断側の観測状態
EExcursion / RecoveringBlocked直後の最初のAccessible。暫定回復
HHealthy安定確認後のEstablished Accessible

なぜ Recovering なのに R じゃなくて E？

Eの分析上の由来は “Accessible excursion after Blocked” にゃ。 もともと履歴付きモデルで、Blocked直後に一回だけ現れるAccessible状態を通常のAccessibleと分けるために E として切り出した。その後、回復設計ではこの状態を人間向けに Recovering / provisional recovery と呼んでいる。

B / Blocked --success--> E / Excursion (Recovering) E / Recovering --stable confirmation--> H / Healthy E / Recovering --failure--> B / Blocked

Recovery terms

復旧設計の言葉

state

A / Accessible

stream-status と conversation snapshot の関連観測が両方ともaccessibleだったペア観測。

雑に言うと：その観測では読めた。

state

B / Blocked

公開traceでblocked regimeを表すペア観測。

雑に言うと：その観測ではダメだった。

state

E / Recovering / provisional recovery

Blocked直後の最初のAccessible観測。established Accessibleとは次状態挙動が異なったため別状態として扱う。

雑に言うと：一回開いた。でもまだ信用するな。

state

H / Healthy

stable confirmation後のEstablished Accessible状態。

雑に言うと：ようやく安定復旧扱い。

control

Recovery hysteresis

一回成功しただけではfailure historyをリセットせず、stable recoveryを宣言しないルール。

雑に言うと：成功一発で浮かれない。

control

Single-flight

多数のローカル復旧triggerを、一つの論理的network recovery ownerへまとめること。

雑に言うと：復旧係は一匹だけ。

observation

Cheap observation

高価なsnapshot materializationより先に使う、小さなstate/version確認という概念。

雑に言うと：いきなり全部取りに行かず、まず小さく見る。

materialization

Snapshot materialization

UI reconcileに必要な、読めるconversation representationを取得・構築すること。

雑に言うと：会話本体をちゃんと持ってくる重い処理。

retry

Start-anchored retry

start-to-start間隔を基準にretryを予定し、fast failureが次retryを自動的に早めないようにする方式。

雑に言うと：429が速く返ったからって次を早押ししない。

load

Retry amplification

論理的な復旧需要に対して、network recovery attemptがどれだけ増えたか。

network recovery attempts / logical recovery demand
architecture

Transport Survival Plane

transport attemptやconnectionが変わってもdurable application stateを生き残らせる、という復旧原則。

雑に言うと：線が切れても仕事そのものまで死んだことにしない。

architecture

Provider-friendly recovery

利用者の回復を助けつつ、不要なduplicate work・retry・bytes・queue growth・materialization costを減らそうとする設計。

雑に言うと：自分も鯖も殴らない復旧。

Model & validation terms

分析・数理モデルの言葉

Pressure knee

負荷、latency、rejection、recovery behaviorなどが急に変化し始める領域。

ρ / utilization

ローカルcongestion simulationで、recovery traffic追加前の exogenous foreground offered work / nominal service capacity。

Trace-preserving replay

観測済みstate sequenceを固定したまま、何をmaterialize/transferしたかだけ変えるcounterfactual accounting。production causalityの推定ではない。

Posterior predictive check

fitted modelの下で、観測パターンがどれくらい起こりそうかを見るBayesian check。

Change point

時系列の平均などの性質が変わる位置を統計的に選ぶ考え方。

AR(1)

直前のresidualが次のresidualに影響するone-step autoregressive model。

u_n = phi * u_(n-1) + epsilon_n

DCS / dissociated control state

部分的に独立したsubsystemが、同時に異なるoperational stateを取り得るというsystems-engineering framing。

Visualization ≠ Evidence

repo全体の原則。図やアニメーションは説明用であり、それ自体がhypothesisをobserved factへ格上げすることはない。
