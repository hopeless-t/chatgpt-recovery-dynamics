# Purrtocol Variant Foundry / パケニャ亜種鋳造所

> Fork the cat. Keep the lineage. Preserve the evidence boundary.

## What this is

A public entry point for creating and indexing Purrtocol derivatives.

A derivative may be a new visual form, 3D rig, educational world, localization, simulator, game, terminal character, protocol specialization, or deliberately wrong negative-example strain.

## Minimal variant manifest

Use `purrtocol-variant/v1`.

Required identity fields:

- `variant_id`
- `name`
- `status`
- `parent_variant_id`
- `origin`
- `mutations`
- `preserved_invariants`
- `evidence_status`
- `license`

Schema: https://github.com/hopeless-t/chatgpt-recovery-dynamics/blob/main/data/purrtocol_variant_schema.json

Example: https://github.com/hopeless-t/chatgpt-recovery-dynamics/blob/main/examples/purrtocol-variant.example.json

## Canonical root

```text
PKV-CANONICAL
└── your fork
    └── somebody else's fork
        └── increasingly questionable cat
```

Lineage is descriptive provenance, not approval or ranking.

## Invariants worth carrying forward

- Recover. Don't amplify.
- Visualization != Evidence.
- UNKNOWN != retry permission.
- Observer/recovery side != omniscient backend.
- Concept != implemented artifact.
- First success != necessarily Healthy.
- Observe before expensive materialization.

## Submission

Fork freely. A fork does not need upstream permission.

If you want canonical discovery/indexing, submit the variant manifest in a PR using the Purrtocol Variant template.
