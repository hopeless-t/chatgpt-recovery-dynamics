Failure Field Guide

その症状、
何が言えるにゃ？

症状を見た瞬間にroot causeを透視しないためのフィールド図鑑。各カードは「観測」「言えないこと」「次の一手」を分離する。

Field rule: Symptom → inference は一段ずつ。UNKNOWNを想像で埋めない。
HTTP 429
OBSERVE

Too Many Requests statusが返った。

DO NOT INFER

固定1分窓、account-scoped limiter、特定backend原因。

NEXT

Retry-Afterがあれば尊重。重複retryを増やさない。

Transport timeout
OBSERVE

期限内に結果を受け取れなかった。

DO NOT INFER

外部作用が未実行だった。

NEXT

operation identityを保ち、durable stateを再観測。

Blank / partial UI
OBSERVE

user-visible renderingが不完全。

DO NOT INFER

canonical dataが消失した。

NEXT

last-known-goodを保ち、cheap state observationを優先。

Resume 404
OBSERVE

resume requestが404だった。

DO NOT INFER

conversation snapshotが必ず失敗する、後の429原因である。

NEXT

snapshot availability等を別軸で観測。

First success after Blocked
OBSERVE

Accessible observationが一回得られた。

DO NOT INFER

stable Healthyへ完全復旧した。

NEXT

E / Recoveringとしてstable confirmationを待つ。

Pretty architecture diagram
OBSERVE

図が存在する。

DO NOT INFER

内部topologyがその通り。

NEXT

図のevidence classを確認。Visualization ≠ Evidence.
