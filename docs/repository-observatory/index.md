# Repository Observatory

> Observe the repository, improve the smallest useful layer, verify, and re-observe.

## North Star

**Maximize useful, forkable, reproducible recovery knowledge and Purrtocol delight while keeping the evidence boundary stronger than the expansion rate.**

## Loop

```text
state
  ↓
observe
  ↓
biopsy
  ↓
competing explanations
  ↓
small reversible change
  ↓
verify
  ↓
promote
  ↓
re-observe ↺
```

The fast path runs on every push and pull request. A scheduled audit catches drift that is not associated with an active change.

## Canonical raw improvement evidence

`data/improvement_events.jsonl`

The ledger is append-only in spirit: old observations are not rewritten to make later changes look cleaner.

## First specimen

`RIL-001` records the 3D First Light repair cycle.

The first GLB failed JSON parsing. A two-character binary corruption was repaired. The next run failed because the contract hash was now stale. Metadata and lineage were rebound to the repaired artifact. All required checks passed. PR #4 was merged.

## Cross-repository learning

The observatory deliberately reuses proven disciplines from the owner's other repositories:

- Finite RAM Lab: append-only evidence, rebuildable projections, observer hygiene;
- MVCA: attempt/operation separation and fail-closed uncertainty;
- Finite Tool Surface Lab: compact references and digest-bound reproducibility.

Cross-repository inspection does not silently mutate the source repository.

## Subjective boundary

Purrtocol delight is a real design objective.

It is not turned into a fake numerical scientific metric.

**Visualization != Evidence.**
